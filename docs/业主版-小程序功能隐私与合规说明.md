# 花语云萃小程序功能、隐私与合规说明（业主版）

更新时间：2026-03-20

适用对象：花语云萃业主/住户

本文档的目的，是在小程序发布前，向业主清楚说明：

- 这个小程序是做什么的
- 为什么需要实名
- 为什么涉及钱包和提现时需要绑卡
- 平台会收集哪些信息、分别用来做什么
- 平台如何降低信息泄露、资金风险和法律风险
- 业主最关心的问题，应该怎样理解

---

## 一、这到底是一个什么小程序

这是一个面向花语云萃业主/住户的小区服务小程序，不是面对社会开放的匿名平台，也不是谁都能进的陌生人交易市场。

当前主要提供的功能包括：

- 社区任务
  - 发布任务
  - 接单
  - 提交完成
  - 确认完成
  - 取消与退款
- 闲置商品
  - 发布闲置物品
  - 图片审核
  - 站内沟通
  - 购买与交易记录
- 社区活动
  - 活动参与
  - 到点统一开奖
  - 奖励记录
- 钱包能力
  - 钱包明细
  - 收入记录
  - 提现申请
  - 提现状态查询
- 站内消息
  - 任务沟通
  - 商品沟通
  - 活动结果通知

这类功能的核心目标，不是“把大家的信息集中起来公开”，而是给本小区住户提供一个更可追溯、更有身份门槛、更适合社区内使用的工具。

## 二、为什么业主可以放心使用

这不是一个“谁下载谁都能用”的开放平台，而是从设计上就设置了门槛和留痕机制。

### 1. 只对合作小区开放

当前注册和使用范围只面向合作小区人员。注册时会校验：

- 微信登录身份
- 手机号授权
- 实名信息
- 小区选择
- 小区范围定位校验

非合作小区用户，无法按正常流程通过验证。

### 2. 不是匿名使用

平台不是“随便起个昵称就能收钱、发任务、参与活动”的模式。涉及交易、活动、钱包、提现等核心功能时，需要实名核验。

平台当前的真实控制逻辑包括：

- 同一个微信身份只允许存在一条实名记录
- 同一个身份证只允许注册一次
- 非本人信息、重复身份、异常注册会被拦截

这意味着，平台上的用户不是完全匿名的，出现纠纷、欺诈、恶意骚扰时，平台可以基于留存记录协助处理。

### 3. 敏感信息默认不是公开的

平台不是做“业主通讯录”。

默认情况下：

- 身份证号码不会对其他用户公开
- 身份证照片不会对其他用户公开
- 银行卡信息不会对其他用户公开
- 完整手机号不会默认公开

尤其是手机号，平台当前采用的是“默认脱敏显示、必要时申请、对方同意后才展示完整号码”的方式，而不是所有人一上来就能看到别人的完整联系方式。

### 4. 资金不是走私人转账

平台的资金链路不是“个人微信转给个人微信”这种不可控模式，而是走正规支付与结算链路，包含：

- 小程序支付
- 延时分账
- 原路退款
- 钱包记录
- 提现申请与状态查询

这样做的好处是：

- 资金去向有记录
- 退款有链路
- 收入有明细
- 提现有状态
- 出问题时可以查

### 5. 聊天、订单、提现、派奖都有记录

平台不是“聊完就没了，钱转完就没痕迹”的模式。当前系统已经有：

- 任务记录
- 商品交易记录
- 钱包流水
- 提现申请记录
- 活动参与记录
- 中奖记录
- 派奖记录
- 管理员审计日志

对正常用户来说，这些记录是保护；对恶意用户来说，这些记录也是约束。

## 三、平台会收集哪些信息，这些信息分别有什么用途

平台不是无理由收集信息，而是围绕“身份校验、社区准入、交易履约、资金结算、纠纷处理”这几个目的按需收集。

| 信息类型 | 主要用途 | 是否默认向其他用户公开 |
| --- | --- | --- |
| 微信身份标识（如 OpenID） | 登录识别、账号唯一性校验、权限控制 | 不公开 |
| 昵称、头像 | 页面展示、聊天识别、交易沟通 | 在必要页面展示 |
| 手机号 | 账号确认、必要联系、任务场景联系授权 | 默认脱敏，不默认公开 |
| 真实姓名、身份证号、身份证照片 | 实名校验、身份唯一性校验、支付/结算开户、风控留痕 | 不公开 |
| 所属小区、楼栋、门牌 | 验证是否为本小区住户，便于社区场景履约与筛选 | 不对所有人公开，仅在必要业务场景按需使用 |
| 定位信息 | 注册时验证是否位于小区范围内 | 不公开，不做持续公开展示 |
| 任务、商品、活动参与信息 | 提供任务、闲置、活动等核心服务 | 对相关页面或相关方可见 |
| 聊天记录、投诉材料、完成凭证 | 争议处理、证据留存、风控审核 | 仅相关方和必要的管理员处理使用 |
| 银行卡与提现信息 | 提现到账、账户校验、结算处理 | 不公开，页面展示为脱敏卡号 |
| 钱包流水、支付状态、退款状态 | 收支核对、资金追踪、异常处理 | 不向无关用户公开 |

简单说，平台收集信息的逻辑不是“多收集”，而是“只在确实需要这项功能时才处理这类信息”。

## 四、平台具体怎么保护业主隐私

### 1. 注册时不是一上来就把所有资料长期上传

当前实名流程里，身份证照片不是在“刚打开页面”时就自动上传，而是用户点击提交后才上传用于核验。

并且已经做了以下控制：

- 用户只是选择了身份证照片，但没有正式提交，不会提前走实名核验链路
- 核验失败或调用异常时，会清理上传文件，尽量避免无效残留
- 成功后的实名资料，仅用于实名、支付/结算开户等必要场景，不对其他用户公开

### 2. 手机号不是默认公开

平台当前不是“只要看得到这个人，就能拿到完整手机号”。

实际规则是：

- 默认只展示脱敏手机号
- 只有在任务等明确业务关系中，相关方才能发起“申请查看手机号”
- 只有被查看的一方主动同意后，另一方才能看到完整号码

这比微信群、线下拉群、随意互加联系方式更可控。

### 3. 定位不是持续跟踪

定位的主要用途，是注册时验证“是不是在本小区范围内”，而不是实时追踪业主每天在哪里。

平台当前的定位逻辑重点是：

- 用户主动点击“获取定位”后才进行校验
- 用于判断是否在当前合作小区范围内
- 不是后台长期监听位置
- 不是把您的轨迹公开给其他人

### 4. 银行卡不是公开资料

绑卡的用途是提现，不是展示。

当前平台对银行卡信息的处理原则是：

- 其他用户看不到您的银行卡信息
- 页面展示的卡号是脱敏形式
- 提现前会校验身份和卡信息是否匹配
- 同一账号同时只允许存在一笔处理中提现，避免重复操作和混乱

### 5. 协议是明确展示并留痕的

用户在注册实名时，需要阅读并同意：

- 《用户服务协议》
- 《隐私政策》

并且系统会记录用户同意的是哪一版协议，而不是口头默认。

### 6. 平台不会出售个人信息

平台隐私政策已经明确：

- 不会把个人信息出售给其他组织或个人
- 只有在提供服务所必需、您单独授权、或法律法规要求的情况下，才会在必要范围内使用或对外提供相关信息

## 五、为什么需要实名

很多业主最关心的问题是：为什么一个社区小程序还要实名？

原因并不是“想多拿大家资料”，而是因为只要平台涉及任务、交易、活动、钱包、提现，就必须解决“这个人到底是谁、出了问题能不能追溯”的问题。

实名的主要作用有以下几点：

### 1. 防止外来人员和匿名账号混入

如果没有实名和小区核验，任何人都可以假冒业主进入平台：

- 发假任务
- 卖问题商品
- 骗取活动奖励
- 恶意骚扰住户

实名和小区校验，本质上是在给真正的业主建立一道门槛。

### 2. 保护正常交易用户

社区任务、闲置交易、活动参与，都不是纯浏览行为，一旦涉及：

- 付款
- 接单
- 奖励发放
- 提现
- 投诉与纠纷

平台就必须知道参与人是真实存在、可追溯的。

否则一旦出现：

- 虚假完成
- 收钱不履约
- 恶意退款
- 多账号刷奖励
- 冒用身份

正常用户反而得不到保护。

### 3. 满足支付和结算的合规要求

只要涉及资金结算，实名就不是“可有可无”的选项。

平台的钱包、奖励、提现等能力，背后都依赖正规支付与结算链路，而这些链路本身就要求：

- 账户身份清晰
- 收款主体明确
- 记录可追溯

### 4. 方便纠纷处理和证据留存

一旦发生任务纠纷、交易争议、虚假信息、恶意行为，平台才有基础去做：

- 记录核对
- 证据保全
- 风险标记
- 临时限制
- 协助处理

如果没有实名，平台只能变成“谁都可以来、出了事谁都找不到”的高风险工具。

结论很简单：

实名不是为了增加麻烦，而是为了把这个小程序做成“对正常业主更安全、对恶意用户更有约束”的社区工具。

## 六、为什么需要绑卡

很多人会问：为什么已经实名了，还要绑卡？

因为“实名”解决的是“你是谁”，而“绑卡”解决的是“钱应该打到哪里、怎么证明是打给你本人”。

### 1. 绑卡是为了提现，不是为了公开银行卡信息

平台要求绑卡，主要发生在以下场景：

- 任务收入需要提现
- 商品交易收入需要提现
- 活动奖励进入钱包后需要提现

也就是说，绑卡主要是“收款出口”，不是浏览功能的前提。

### 2. 防止打错款、冒领和盗领

如果没有绑卡和校验，就会出现很多风险：

- 钱打到别人的卡
- 用户随便填一个无关账户
- 冒用身份提现
- 奖励或收入被错误领取

绑卡的本质，是让“收入只能进入与本人身份一致、经过校验的收款账户”，这对业主其实是保护。

### 3. 正规支付结算机构本身就要求收款账户校验

平台不是靠管理员手工转账，也不是靠私人收款码逐笔打钱，而是走正规支付/结算链路。

这类链路本身就会要求：

- 收款账户信息
- 实名一致性
- 提现方式校验
- 银行或支付机构状态确认

所以绑卡不是平台额外增加的负担，而是为了把“到账”这件事做得更规范、更安全、更可追踪。

### 4. 平台对绑卡信息也做了最小化处理

当前实际口径是：

- 绑卡主要用于提现和到账
- 已绑卡信息对其他用户不可见
- 页面中展示的是脱敏卡号
- 提现前会检查卡信息是否就绪
- 提现过程中会记录状态，避免重复提交

所以可以把绑卡理解成一句话：

不是“把银行卡交给平台”，而是“告诉正规结算链路，钱该安全地打到哪张属于你本人的卡里”。

## 七、为什么平台目前会扣除 4%

很多业主也会关心：为什么平台会有 4% 的扣除？

这部分需要直接说明清楚，避免大家误解为“隐形收费”或“随意抽成”。

### 1. 这 4% 的口径，本质上是试运营阶段的平台技术服务费

当前平台仍处于试运营阶段。

目前的公开口径是：

- 对涉及平台支付、结算、钱包入账、提现等资金链路的场景
- 暂按 `4%` 的平台技术服务费口径执行

这不是为了把钱“扣走不说明”，而是为了让平台能够持续运转下去。

### 2. 为什么不是完全免费

这个小程序从一开始到现在，很多成本都不是外部赞助，而是平台自己承担。

目前主要成本包括：

- 实名相关的开户、业务接入与结算准备成本
- 小程序本身的设计、开发和实现成本
- 云开发、数据库、文件存储、图片审核、消息等技术成本
- 支付平台本身收取的通道手续费
- 日常服务维护、故障处理、功能修复和后续优化成本

简单说，这个小程序不是“零成本挂个页面”就能长期运行的工具，背后确实存在持续投入。

### 3. 为什么现在要收这部分费用

平台当前采用 4% 的口径，主要是出于两个现实原因：

- 一部分是为了覆盖支付平台和相关技术服务本身就会产生的手续费与运行成本
- 另一部分是因为平台前期开户、接入、开发、上线和维护投入目前基本都是自费承担，需要逐步回本，才能把服务继续做下去

如果完全不考虑这些成本，平台短期可以运行，但长期很难稳定维护，也很难继续优化。

### 4. 这不是永久不变的最终口径

这一点也需要和业主说明白：

- 当前 `4%` 是试运营阶段的口径
- 试运营期暂按 `一年` 来看
- 后续会结合真实使用情况、平台实际成本和业主反馈，再评估是否调整

也就是说，`4%` 不是承诺永久固定不变，更不是“以后只会越来越高”。

如果后续：

- 使用量更稳定
- 实际成本更清晰
- 平台回本压力下降
- 业主对收费口径有更明确反馈

平台会再评估是否优化或调整。

### 5. 平台会尽量做到收费透明

对于业主来说，真正重要的不是“绝对一分钱不收”，而是：

- 收费原因是不是说得清楚
- 收费规则是不是公开透明
- 有没有提前说明
- 后续调整会不会提前公示

平台当前的态度是：

- 不做隐形收费
- 不做临时乱加价
- 对现阶段为什么是 `4%` 讲清楚
- 后续如有调整，会尽量提前公示

一句话概括就是：

当前扣除 `4%`，不是为了额外增加大家负担，而是为了覆盖支付和技术运行成本、回收前期自费投入，并在试运营这一年里把小程序稳定运行起来。

## 八、平台如何降低法律风险

很多业主担心的“法律风险”，一般集中在以下几个方面：

- 这个平台是不是非法收集信息
- 这个平台是不是谁都可以匿名发东西
- 交易出了问题谁负责
- 活动抽奖会不会变成赌博或不透明玩法
- 平台是不是在私下收款、私下分钱

从当前产品设计和系统实现看，平台是在主动规避这些高风险点。

### 1. 平台定位不是匿名灰色交易工具

平台已经明确采用以下口径：

- 面向合作小区住户使用
- 核心功能建立在实名和小区核验基础上
- 平台提供的是信息展示、技术支持、撮合协助、风控审核、证据留存、结算记录和争议协助处理

这意味着平台不是做“匿名拉活”“匿名出货”“匿名转账”。

### 2. 对违法违规内容和异常行为有拦截与处置能力

平台规则已经明确禁止：

- 违法违规任务
- 高风险或不适合社区场景的交易
- 虚假信息
- 骗补贴、骗退款、刷奖励
- 冒用身份
- 套现套利
- 恶意骚扰

对异常行为，平台保留采取以下措施的能力：

- 限制发布
- 限制交易
- 延迟结算
- 暂停提现
- 保全证据
- 下架内容
- 追回错误发放款项

这不是在为正常用户增加负担，而是在给平台秩序做底线控制。

### 3. 活动玩法不是住户之间互相下注

当前活动功能的设计重点是：

- 只有管理员可以发布活动
- 活动会公示开奖时间、总金额、中奖人数等规则
- 用户是在活动期内报名参与
- 到点统一开奖
- 开奖结果、中奖记录、派奖记录都可留痕

这和“住户之间私下押注、对赌、互相转现金”的模式完全不同。

换句话说，平台当前是在主动避开“用户之间现金对赌、匿名抽奖、无记录发奖”这类高风险玩法。

### 4. 资金走记录链路，不走口头链路

平台不是“到时候看管理员心情转钱”，而是把：

- 支付
- 分账
- 退款
- 钱包流水
- 提现状态

都落到可追溯的系统记录里。

对于业主来说，凡是“有记录、能查询、可追溯”的模式，都比“私下转账、口头承诺、群里喊一声”更安全。

### 5. 平台不承诺零风险，但会尽量把风险降到可控

任何互联网产品都不能承诺绝对零风险，但可以做到：

- 提高门槛
- 减少匿名
- 最小化公开
- 保留证据
- 对异常行为有约束
- 对资金流向有记录

这正是当前这个小程序的设计方向。

## 九、业主最关心的几个问题

### 问题 1：我注册之后，其他业主会不会看到我的身份证和银行卡？

不会。

身份证号码、身份证照片、银行卡信息都不是面向其他用户公开展示的资料。银行卡页面展示也是脱敏卡号，不会把完整卡信息公开给其他用户。

### 问题 2：我的完整手机号会不会被所有人看到？

不会。

平台当前默认只显示脱敏手机号。只有在任务等明确业务关系中，相关方发起申请且您同意后，完整手机号才会显示给对应的人，不是全平台公开。

### 问题 3：为什么注册时还要定位？

因为平台是特定小区使用场景，定位的主要用途是验证注册人是否确实在小区范围内，减少外来账号冒充住户。

这不是为了持续跟踪大家的位置，也不是为了公开个人行动轨迹。

### 问题 4：我不想提现吗，还需要绑卡吗？

如果只是正常浏览或使用不涉及提现的部分功能，不一定立刻需要绑卡。

绑卡主要是为以下场景准备的：

- 您有任务收入
- 您有商品交易收入
- 您中了活动奖励并希望提现

也就是说，绑卡主要是“提款用”，不是“注册就必须把银行卡交出去”。

### 问题 5：为什么平台目前会扣除 4%？

因为平台现在还在试运营阶段，很多成本都是平台自己先投入的。

当前这 `4%` 主要用于覆盖：

- 开户和支付结算接入相关成本
- 小程序开发实现成本
- 云服务、审核、存储、维护等技术成本
- 支付平台本身的手续费

平台这样做，不是为了隐形收费，而是为了让系统能稳定运转，并逐步回收前期自费投入。

同时也会和业主明确说明：

- 当前按 `4%` 试运营口径执行
- 试运营期暂按 `一年`
- 后续会结合实际情况和大家反馈再评估是否调整
- 如果调整，会尽量提前公示

### 问题 6：这个平台是不是会乱用我的信息？

平台当前已经明确了信息使用范围，核心是：

- 注册与实名
- 小区身份核验
- 交易与任务履约
- 钱包与提现
- 风控审核
- 纠纷处理

不会因为您注册了，就把您的敏感信息当成公共资料到处展示或出售。

### 问题 7：如果发生纠纷，平台能做什么？

平台可以基于现有记录协助处理，包括：

- 查看任务记录
- 查看交易记录
- 查看聊天记录
- 查看提现和派奖记录
- 保留投诉材料
- 对异常账户做临时限制

但也需要说明，具体的买卖或履约关系本质上仍然是用户之间的民事关系。平台的作用是提供规则、留痕、风控和协助，而不是把一切都变成无法律责任的“平台全兜底”模式。

## 十、平台给业主的明确承诺

1. 本小程序不是对社会开放的匿名平台，而是面向合作小区住户使用的社区工具。
2. 敏感信息不做默认公开展示，尤其是身份证、银行卡、完整手机号。
3. 手机号默认脱敏，完整号码只在必要场景并经本人同意后展示。
4. 定位主要用于注册时的小区范围核验，不做日常持续跟踪展示。
5. 实名和绑卡不是为了增加门槛，而是为了提高社区安全、交易可追溯性和资金到账安全。
6. 钱包、奖励、提现、退款等资金动作尽量走有记录、可查询、可追溯的正规链路。
7. 当前试运营阶段的 `4%` 扣除口径会尽量公开说明，后续如有调整，也会尽量提前公示。
8. 对虚假身份、欺诈、恶意退款、刷奖励、套现等异常行为，平台会保留风控和处置能力。
9. 用户可以在小程序内查看《用户服务协议》和《隐私政策》，平台也会对协议更新进行公示。
