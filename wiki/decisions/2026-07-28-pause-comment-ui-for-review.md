# 送审替换候选暂时隐藏评论界面

## 背景

已上传的开发版本 `2.4.0@68382f5` 包含评论入口，但微信审核未通过。用户要求先让
替换候选完全不显示评论文字、数量、气泡、弹层、权益或通知，同时保留后端、审核、
治理和历史数据，以便以后通过新的审核版本恢复。

## 评估选项

1. 删除评论组件、接口和生产数据。隐藏最彻底，但不可逆且会破坏历史审核和治理
   证据，不采用。
2. 使用远程配置，在审核通过后热开启。会使审核版本与实际上线能力不一致，不采用。
3. 使用确定性的客户端发布开关，保留后端；服务端只为新版消息请求排除评论通知。
   可验证、可恢复并保持旧客户端合同兼容，采用。

## 最终决定

送审替换候选通过 `hyyc/config/product-features.js` 将 `comments` 固定为 `false`。
资讯列表、资讯详情、会员权益、消息中心和个人资料页面不得显示评论相关 UI 或文案；
历史 `comments=1&commentId=...` 与 `from=comments` 深链也不能重新打开评论。

客户端四个消息 action 显式发送 `includeComments:false`，`knowledgeFeed` 在参数缺失
时仍按 `true` 处理以兼容旧客户端；新版请求沿已有 `owner_created_at` 索引分批向后
查找非评论消息，客户端再做一次兼容格式过滤。关闭态拒绝“全部已读”，避免修改隐藏
评论通知的历史已读状态。该服务端变更只需 code-only 部署，不增删集合、索引或数据。

评论组件、接口、后台审核、治理和历史数据继续保留，不删除生产数据。

## 影响

- 审核候选的资讯操作栏只保留喜欢、收藏和分享。
- 消息中心仍显示会员和资料通知，评论通知不占用其 50 条可见消息容量。
- 已上传的 `2.4.0` 和误带服务端源码的 `2.4.1` 均已由安全评论隐藏开发版本
  `2.4.2` 替换；前两者不得提交审核。
- 旧正式客户端未传 `includeComments`，继续保持原有消息合同。
- 评论恢复不能远程完成，必须修改开关、更新回归并提交新的微信审核版本。

## 恢复边界

以后恢复评论时，修改中央发布开关并同步更新锁定关闭态的发布测试，再完整执行
`npm run verify`、微信开发者工具 UI canary 和新的微信审核提交。不得把本决定实现为
审核通过后远程热开启；恢复评论属于新的客户端送审版本。

## 验收

- 关闭态运行时不展示评论文字、评论气泡、评论入口、评论弹层或评论消息。
- 旧评论深链和处理函数在关闭态均拒绝打开评论。
- 会员权益和资料文案不再声明评论能力。
- “我的”通用消息入口使用信封，不再使用聊天气泡图形。
- 开关恢复为 `true` 时，既有评论组件、权限和数据路径仍保留。
