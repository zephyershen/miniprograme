# CloudBase 模型成本、共享资源点与 Packy 混合路由测算

> 2026-07-21 的生产实测已把内部 AI 月上限从 20,000 调整为 60,000 点，并把统一 60 秒后台超时拆为分析 90 秒、简报 180 秒、同步审核 30 秒。最新证据见 [CloudBase 超时、无图资讯与动手课生产复核](2026-07-21-timeout-feed-and-manual-production-validation.md)。本页的 20,000 点与 60/10 秒描述保留为切换当时的历史基线，不再代表当前配置。

## 结论

- 产品负责人已明确授权立即执行：2026-07-20 环境不可逆切换为资源点计费，CloudBase 作为主模型、Packy 作为自动兜底。数据库、云函数、存储、流量、日志和模型 Token 共用标准版每账期 330,000 点。
- 切换后控制台核验 `EnvDeductionMode=credits`、超限按量关闭；当时账期已使用约 14,100 点、约剩 315,900 点。1,000 点等于 ¥1 的换算不代表超额固定为 ¥2；超限费用取决于实际消耗，且当前未开启自动超限按量。
- 依据 2026-07-15 至 2026-07-19 的真实监控曲线，当前基础设施按最近完整日外推约消耗 140,000～170,000 点/月，尚未包含无法精确取得的日志点数。最大项是数据库操作和云函数计算，不是模型 Token。
- 按当前资讯量和已观测的约 766 Token/条分析估算，CloudBase 文本分析、简报与早期用户审核可先预留 5,000～20,000 点/月。因此即使暂不优化，早期总量约为 150,000～190,000 点/月；优化分钟任务后预计可明显低于该区间。
- Packy 兜底只能节省模型 Token 点数，不能解决数据库、云函数、CDN 或日志耗尽。月度预测超过 230,000 点或预计剩余低于 100,000 点时，应把新增模型任务切到 Packy，同时保留至少 100,000 点给读取、支付和会员鉴权。

以上月度数字是“官方单价 × 当前真实监控”的工程外推，不是腾讯云账单承诺。资源点上报存在延迟，切换后必须同时维护应用内调用台账。

## 官方计费边界

- 新标准版为 ¥199/月、330,000 点/月，1,000 点折合 ¥1；资源点共同抵扣数据库、云函数、存储/CDN、API、日志、工作流和模型 Token。
- 旧固定配额标准版没有被整体强制迁移，不切换仍可继续使用；自 2026-06-17 起，CloudBase 内置模型必须使用资源点计费。
- 资源点模式切换不可逆。抵扣顺序为套餐资源点、额外资源包、按量付费；用量数据存在上报延迟。
- 常用模型在不超过 128K 上下文时，`qwen3.5-flash` 输入/输出分别约 ¥0.2/¥2 每百万 Token，`qwen3.5-plus` 分别约 ¥0.8/¥4.8 每百万 Token。公开多模态目录当前列出 `qwen3.5-plus`，未列出 `qwen3.5-flash`，所以图片审核不能只凭价格表假定 flash 可用。

## 当前真实资源外推

当前账期为 2026-07-15 至 2026-08-14。最近完整日 2026-07-19 的主要计量为：

| 项目 | 当日计量 | 官方换算 | 约当资源点/日 |
| --- | ---: | ---: | ---: |
| 数据库读写 | 156,189 次 | 200 点/万次 | 3,124 |
| 云函数计算 | 11,733,580,800 MB·ms | 0.11108 点/GBs | 1,273 |
| CloudBase API | 18,639 次 | 100 点/万次 | 186 |
| 小程序 API | 370 次 | 200 点/万次 | 7 |
| 函数调用、出流量和当前存储 | 小量 | 按官方单价 | 约 20 内 |

合计约 4,600 点/日，30 日约 138,000 点；此前两个高活动日折算更接近 150,000～180,000 点/月，因此以 140,000～170,000 点作为当前基础预算区间更稳妥。日志资源点尚未包含，正式切换后应从资源点明细补齐。

`knowledgeFeed` 最近 51 次定时调用平均 14.76 秒，中位数 4.95 秒，P95 71.65 秒，函数为 512 MB。定时计算自身按当前平均外推约 35,000 点/月；这证明先优化任务编排比更换文本模型更能释放余额。

## 模型预算假设

- 当前生产分析平均约 766 Token/条。近期日志时段外推约 80～160 条/日，按更保守的上游规模审计可到约 300 条/日，因此以每月约 2,400～9,000 条、约 180 万～690 万总 Token 做预算。
- 按既有样本约 58% 输入、42% 输出，并使用 `qwen3.5-flash` 官方价估算，资讯文本分析约 ¥1.7～¥6.6/月，即约 1,700～6,600 点。
- 日/7 日/30 日滚动简报、文本审核、昵称审核及早期图片审核再留出余量后，首发按 5,000～20,000 点/月预算更稳妥。
- 图片没有统一“每张固定价格”或公开的分辨率换 Token 公式。应先用真实图片样本测量 P50/P95 Token，再确定 flash 是否能在当前环境处理图片；未验证前使用 `qwen3.5-plus`。

## 当前浪费与可释放空间

单个每分钟触发器串行执行两路源同步、视觉 worker、分析 worker和三种简报检查。只读代码审计发现：

1. 两路同步每分钟重复请求相同指纹；
2. 最多 500 条的精选缓存每分钟被完整读取多次；
3. 归档统计每分钟读取最多 90 个完整日归档；
4. 无视觉任务时仍反复获取和释放租约；
5. 08:10 后每分钟重复检查三份当日简报；
6. 三份简报每天各做一次最多 12,000 条的覆盖率扫描。

在不改变用户体验的前提下，拆分调度频率、复用指纹和缓存、把归档统计改为聚合字段、让简报检查按到期时间触发，预计可释放约 50,000～80,000 点/月。此数是代码路径外推，需以改造后的 48 小时至 7 天监控确认。

## 已实施的混合路由

1. 资讯分析和文本审核使用 `qwen3.5-flash`；简报和图片审核使用 `qwen3.5-plus`。两款模型已在 CloudBase 控制台启用。
2. CloudBase 遇到 429、5xx、超时、严格结构失败、月度模型预算不足或真正越过月上限时，自动路由至 Packy；任务 ID 保持幂等，避免双写或重复公开。
3. `knowledge_ai_budget` 按上海自然月原子预留；切换当时内部月度硬上限为 20,000 点，2026-07-21 已提高到 60,000 点。输出按上限的 2 倍预留，成功后按实耗结算。实耗仍超预留时先原子补差，只有补差会突破月上限时才持久化 `overrunDetected` 并熔断当月主路由。当前 CloudBase 分任务超时为分析 90 秒、简报 180 秒、同步审核 30 秒，Packy 为后台 90 秒、审核 20 秒。
4. 调度拆为八个隔离触发器，简报检查从每天 2,865 次降为 3 次；分析调度减少约 90%，视觉调度减少约 80%，来源 304 不再写库。覆盖统计增加 `analyzedAt_1` 与 `analysis_coverage` 非唯一索引。
5. 客户端增加有界 LRU 缓存、请求合并、自适应退避、隐藏停轮询、图片懒加载与喜欢/收藏最新目标同步。完整回归为 249/249，项目检查覆盖 33 JSON、216 JavaScript 和 9 个活跃页面。

仍需观察 48 小时至 7 天的真实资源曲线。CloudBase 没有数据库/函数/模型之间的平台级优先队列；60,000 点模型上限只能确保本项目模型先于 100,000 点核心保留线退出，不能保证任何异常基础设施流量都永远不会耗尽共享池。
