# GitHub 开源库接入与生产验证

## 来源观察

- 目标是公开可访问的 AIGCLINK 方案库列表，列表提供标题、收录日期、可选摘要、标签、项目地址和详情页标识。
- 公开 reducer 会返回完整 block ID 列表，但单次 record map 只携带约 999 个 block；因此不能把一个大 `limit` 当成全量。使用 `收录时间 <= 最老已取日期` 的包含式分段查询后，当前实测取得 1,727 条全部记录。
- 当前公开集合包含 528 个唯一标签，时间跨度为 2023-10-28 至 2026-07-21；8 条旧记录没有摘要，归一化允许空摘要。
- 项目不抓取或保存详情正文，以减少内容复制、接口负载和上游结构耦合。

## 实现证据

- adapter 集中外部属性映射、富文本清理、HTTPS 地址校验、日期归一化、来源标签处理、分段查询和头部内容指纹。
- sync service 使用分钟级头部指纹、24 小时全量对账、进程内请求合并和数据库同步租约；写入既有条目表并撤回上游已删除记录。历史回填不写按日索引且不批量排视觉任务，避免首次同步产生大队列。
- 客户端 `openSource` 顶部短标签显示 `GitHub` 并使用青绿色激活态；该频道使用连续卡片列表，不渲染日期分组、折叠控件、时间线、时间点或单条时间。“全部”频道继续用既有日期时间线渲染同一批记录。
- 独立频道筛选面板只显示可搜索的 AIGCLINK 标签，不显示 AIHOT 时间、公司和技术方向；所有用户均可查看全量历史。进入“全部”频道后，同一记录继续受普通资讯的时间、主题和权限约束。
- 可见来源名为 `GitHub 开源库`，小头像取自 GitHub 官方 Brand Toolkit 的 Invertocat，并以 Cloud File ID 持久化；AIGCLINK 继续作为内部上游归因。
- 同步合同版本升到 3 时强制完成分段全量同步，之后每分钟检测最新 30 条的内容指纹，变化后同步整个集合，未变化则跳过写入。

## 验证

- 全量 Node 测试 447/447 通过，其中包含分段全量、空摘要、专属标签筛选、全角色历史、开源库独立平铺、“全部”频道时间线保留、名称和头像映射。
- 项目检查覆盖 35 个 JSON、270 个 JavaScript 和 11 个页面；差异检查无空白错误。
- 微信开发者工具登录态正常，CLI 预览构建成功，预览包 372,810 bytes（364.1 KB）。

## 生产验证

- `knowledgeFeed` 已部署同步版本 3。生产 `openSource` 返回 `totalAvailable: 1727`、`resultCount: 1727`，与公开集合分段实测一致；首条使用 GitHub 官方头像，`sourceTagFacets` 返回 528 个原生标签。
- 生产 `MCP` 查询返回 53 条且 `appliedFilters.time` 为 `all`，证明标签与不限时间合同生效。
- 首次全量同步完成后的分钟调用返回 `openSourceLibrary.status: unchanged` 并更新 `polledAt`，证明上游无变化时不会重复全库写入。
- 更新检测是分钟轮询而非上游 webhook；正常新增最长约一分钟进入同步，旧记录编辑由每日全量对账兜底。
