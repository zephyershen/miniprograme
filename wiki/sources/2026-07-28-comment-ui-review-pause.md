# 评论界面送审暂停与开发者工具验收

## 实现

- 新增确定性的客户端发布开关 `PRODUCT_FEATURES.comments=false`。
- 资讯列表和详情隐藏评论动作、数量与气泡；详情旧评论深链被清空，评论处理函数
  fail-closed。
- 会员权益、会员状态、个人资料和资料编辑文案切换为无评论版本。
- 评论通知在共享消息会话层过滤，覆盖现有类型、旧路由字段、嵌套路由/负载字段、
  评论分类和未来未知评论类型；未读数只从可见消息重算。
- 新客户端的消息请求显式发送 `includeComments:false`；服务端复用既有消息排序索引
  分页越过评论通知，保证较早的会员和资料消息不会被最新 50 条评论挤掉。旧客户端
  缺少该参数时仍保持原合同。
- 消息页关闭评论分类和互动列表，只显示系统通知；“我的”消息入口从聊天气泡改为
  信封图标。关闭态前端和服务端均拒绝“全部已读”，不改隐藏评论的历史已读状态。
- 评论组件、接口、后台审核、治理和历史数据没有删除，未来恢复仍由同一中央开关
  控制，但必须作为新客户端版本重新审核。

## 自动验证

最终完整 `npm.cmd run verify` 通过：

- 隔离干净发布工作树为 38 个 JSON、358 个受控 JavaScript、16 个注册页面；
- 792/792 个 Node 测试；
- 29 个 `ADMINONLY` 集合合同和 50 个索引合同；
- 覆盖率与生产依赖审计均通过，客户端检查包约 0.73 MiB；
- 新增小程序打包边界守卫，要求 `project.config.json` 显式排除
  `cloudfunctions / cloudrun / scripts / tests`，并让项目检查直接从同一配置计算包体。

新增关闭态回归覆盖中央开关、资讯列表/详情、旧详情深链、旧资料编辑深链、会员权益、
评论消息过滤、跨页可见消息查找、扫描预算、未读重算、关闭态零批量写、通用消息
信封图标和经中央开关恢复的路径。`git diff --check` 通过。

## 微信开发者工具实画面

开发者工具旧长驻会话的自动化准备状态漂移后，按 CLI 工作流正常 `quit` 并冷启动；
9420 HTTP 服务和临时 9421 automator 均只在本机监听。真实管理员上下文中的六页
canary 全部通过：

- 资讯列表：`commentsEnabled=false`，评论图标为 0；首张卡仅有喜欢、收藏、分享
  三项，连续排列且无空槽。
- 资讯详情：带旧 `comments=1&commentId=...` 查询打开，`commentsOpen=false`、
  `focusedCommentId=''`；评论图标和评论组件均未挂载，操作栏文字仅为喜欢、收藏、
  分享。
- 会员页：六项权益不含评论，可见文字无“评论”。
- 消息页：只显示系统通知，无评论 Tab、互动行、评论未读红点或全局“全部已读”；
  系统通知仍可逐条打开并标记，避免隐藏期间误改评论通知的历史已读状态。
- 我的：资料说明无评论文案，六项权益不含评论，通用消息图标为信封。
- 资料编辑：旧 `from=comments` 查询不会恢复评论流程；页面显示“个人资料”，可见
  说明与隐私文案均不含评论。
