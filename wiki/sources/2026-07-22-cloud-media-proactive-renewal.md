# CloudBase 图片临时签名到期前续签修复

> 2026-07-22 晚间运行态复核更正：TCB 临时地址的 `t` 是签名生成时间，不是绝对过期时间。先前按到期时间解析会把 SDK 刚返回的新地址立即判为不可用，造成资讯图片和来源头像同时留白。以下结论以本次更正为准。

## 现象与根因

- 微信开发者工具先报告资讯列表缩略图 HTTP 403，随后又出现所有资讯图片与来源头像同时留白。
- 数据库只保存 `cloud://` File ID，没有把临时 HTTPS 地址入库；同一文件重新换签后返回 HTTP 200、`image/jpeg`，说明云文件和读取权限正常。
- 微信小程序 SDK 的真实返回同时包含 `status: 0`、`errMsg: ok` 和可访问的 HTTPS 地址；地址中的 `t` 与签名生成时刻一致。客户端把它误当成绝对过期时间后，在媒体 session 的安全窗口判断中立即拒绝全部新地址，因此页面虽然拥有完整 File ID，却只渲染空占位。
- CloudBase 官方也明确说明私有读文件的临时地址会过期，前端不能长期缓存，应在页面加载或到期前重新获取：[CloudBase 小程序云存储说明](https://docs.cloudbase.net/recipes/add-file-upload-wechat-miniprogram)。

## 修复

- 媒体服务不再从 TCB 地址的 `t` 推断过期时间；SDK 明确返回 `maxAge` 时按它提前续签，没有返回时使用有界五分钟 session TTL。
- 临时地址解析兼容当前 SDK 的 `status: 0` 与兼容形态的 `code: SUCCESS`，并统一 `fileID`/`fileId` 后再进入共享媒体 session。
- 媒体 session 继续只缓存 File ID 到当前签名的映射，同时向页面暴露下一次安全续签延迟。
- 资讯首页、详情、会员精选和收藏页在可见期间跟踪当前 File ID，并在安全到期点之前批量强制换签、原位更新页面 URL；页面隐藏时暂停定时器，返回时恢复，卸载或换数据时取消旧续签，避免后台空耗和旧异步结果覆盖新页面。
- 原有单次 `binderror` 强制换签仍作为网络抖动兜底，失败后只隐藏图片，不阻塞文字。

## 验证

- 用户指出的 `Meta 研究：量化让推理模型过度犹豫` 条目在生产数据库和公开 item DTO 中均有头像、列表缩略图和正文预览 File ID；三个对象的新签名均可访问。
- 微信开发者工具自动化在修复前精确复现三个页面 URL 为空；修复后同一条目的头像、列表缩略图和详情原图均写入有效 HTTPS 地址，并通过列表与详情截图肉眼复核。
- 全量 Node 测试 435/435 通过，新增覆盖 `t` 语义、当前/兼容 SDK 成功形态、按 `maxAge` 续签、失败重取和四个长驻页面接线。
- 项目检查通过，覆盖 35 个 JSON、267 个 JavaScript 文件和 11 个页面；`git diff --check` 通过。

## 边界

- 这是客户端版本修复，不需要重新部署云函数，也不会修改云存储对象。
- 旧版本客户端仍包含错误的 `t` 判定；必须重新编译/上传包含本更正的客户端版本后，资讯图片和头像才会恢复。
