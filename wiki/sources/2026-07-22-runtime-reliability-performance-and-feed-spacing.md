# 资讯间距、生产截图链路与运行性能复核

## 范围

- 调整手机端日期时间线中相邻资讯卡片的视觉间距，不改变卡片内部密度、日期标题或时间线宽度。
- 从公网节点、CloudBase 上海函数、视觉任务集合和微信开发者工具四层复核生产链路。
- 只依据本轮可重复实测描述“当前稳定”，不把有限观测写成所有网站、所有时刻都成功的绝对承诺。

## 前端结果

- `pages/inbox/index.wxss` 只给同一已展开日期内的相邻 `.timeline-entry` 增加 `14rpx` 上间距；日期组首项不增加空白，时间线继续跨越卡片间隙。
- 微信开发者工具自动化渲染了 8 条首屏资讯，其中 7 条列表图、7 个来源头像正常挂载，页面没有 feed error；截图肉眼确认相邻卡片已分开且时间线、时间点清晰。
- 同一开发者工具会话中，重新进入资讯页到首批文字和图片同时可用的两次观测约为 7.9 秒和 4.4 秒。该数据包含开发者工具自动化、CloudBase 调用和本地网络，不等同于真机发布包指标；它说明滚动后的数据量受控，但冷启动首屏仍不是亚秒级。
- 首屏服务端只下发 8 条列表 DTO，后续日期和分页按需加载；列表图与头像启用懒加载和批量临时地址换签。忽略云函数、测试和运维脚本后，小程序代码/静态文件约 0.41 MiB；课程手绘图在云存储中，当前课程只签发 3 张，客户端只挂载当前页和相邻页。

## 公网中继与跨站访问

- 节点复核时负载均值为 0，约 486–511 MiB 可用内存，1 GiB Swap 未使用；Nginx 与 WSS 中继 active，最近一小时没有 error 级日志或失败 systemd 单元。
- 节点直连两轮代表站点：X robots 约 0.153/0.159 秒、Twitter widget 约 0.084/0.089 秒、Anthropic 约 0.110/0.122 秒、Hugging Face 约 0.072/0.075 秒、GitHub 约 0.250/0.250 秒，均返回 HTTP 200。
- OpenAI 首页返回 HTTP 403、Reuters 页面返回 HTTP 401，但连接与响应都在约 0.05–0.11 秒完成；这是站点访问策略/挑战，不是网络超时。因此不能宣称“任意网页都一定可抓取”，生产仍需质量闸门和文字降级。
- CloudBase 上海函数到正式 WSS 中继的两次认证探针均 `relayReady=true`、`addressPinned=true`，函数日志内约 561/585ms；真实 X canary 精确命中目标、质量通过、上传 1 张 JPEG，函数执行约 8.4 秒，验收对象随后按精确路径删除。

## 新资讯与视觉队列

- 来源同步每分钟运行一次，视觉 worker 在每分钟 `:10/:25/:40/:55` 运行，单轮最多并发 6 个隔离的 2GB 截图实例。
- 本轮观测到 3 条新视觉任务进入 pending；约 40 秒后的复核为 pending 0、leased 0。最新 30 条活跃资讯中 29 条已有列表图或原图，1 条 X 状态页因 16 秒导航超时进入 retry；其文字保持公开且后续继续退避补图。
- 正常 X 生产截图日志约 6.5–9.1 秒，列表缩略图约 0.7–0.8 秒；长新闻页约 16–27 秒。外站登录墙、删除页、PDF 导航中止或偶发超时仍可能失败，因此“新资讯通常很快补图”成立，“永远无失败、永远无等待”不成立。
- 当前 visual job 集合的 60 条 retry 与 4 条 blocked 是历史故障诊断，不是实时排队；fresh pending 与 leased 均为 0。图片失败最多只影响图片，新的文字资讯最多等待 4 分钟后放行。

## 验证

- Node 测试 436/436 通过，新增相邻时间线卡片间距回归。
- 项目检查通过：35 个 JSON、267 个 JavaScript 文件、11 个注册页面；`git diff --check` 通过。
- 微信开发者工具截图确认列表图、来源头像、时间线和新增间距均实际渲染。

## 边界

- 本轮客户端改动尚未上传体验版或正式版，线上用户需等下一次小程序版本发布。
- 代理节点的当前健康观测不能替代长期可用性监控；外站反爬、登录要求、内容删除和区域策略属于链路外部变量。
- 若目标是把冷启动首屏进一步压到接近即时，需要另行实现按账号与权限隔离的本地快照/stale-while-revalidate，并用真机网络做发布包基准；本轮没有为追求数字而引入可能泄露角色数据的持久缓存。
