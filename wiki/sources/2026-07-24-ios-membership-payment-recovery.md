# iOS 付款成功后会员未生效事故修复与恢复

## 结论

- iOS 收银台已经付款，但页面稍后提示订阅未成功的主故障已修复。生产中的已付款
  记录均已通过微信官方查单恢复权益；没有人工把订单改成已付款，也没有绕过官方
  金额、账号或状态校验。
- 生产只读核对共有 3 笔已付款记录、2 个实际付款账号；3/3 均能匹配有效
  `wechat_virtual_pay` 会员，3/3 均有 `membership_succeeded` 站内消息事件，
  且消息事件全部处理完成。一个账号的多次购买只对应一份累计会员记录，因此不能
  用“付款笔数等于会员文档数”判断漏发。
- 微信发货消息回调现以“官方查单通过 + 权益事务提交成功 + 加密
  `ErrCode=0`”作为正常主路径。`/xpay/notify_provide_goods` 只保留给后台异常
  对账兜底，不再同步阻塞微信回调；兜底请求使用实际发送 JSON 计算 `pay_sig`。
- 客户端会保存“收银台是否已经成功完成”的阶段。付款后服务端暂时无法确认时，
  再次进入只查单和刷新会员，不会重新拉起收银台；同一页面并发双击也会在登录或
  建单前同步拦截。

## 根因

1. `membershipBilling` 从 CloudBase 读取订单时会得到数据库管理字段 `_id`。
   原履约事务把整份订单展开后再 `set`，等同于尝试更新 `_id`，CloudBase 返回
   `-501007 cannot update _id`，会员、已付款订单和成功消息所在事务一起回滚。
2. `xpay_goods_deliver_notify` 回调在权益已经写入后，又同步调用手工发货 API；
   手工接口失败会让回调返回 retry，形成“权益已生效但微信仍反复发货”的闭环。
   微信官方说明正常消息推送返回成功后无需再调用手工通知接口。
3. 客户端没有区分“服务端建单失败、Apple/微信收银台失败、收银台成功后确认失败”，
   会把部分服务端错误误报为 iOS 收银台失败；待确认订单也没有记录收银台已完成
   阶段，用户再次点击存在重复拉起风险。
4. 服务端旧流程在同一账号的并发请求之间缺少原子建单边界，历史待确认订单也可能
   在未完成官方查单时被新订单绕过。

## 修复

- 所有订单、会员和锁文档写入边界统一剥离 `_id`；付款、失败和退款状态使用
  期望当前状态的事务转换，旧的 pending/failed 快照不能覆盖 paid，旧的 paid
  快照也不能在退款后重新发放会员。
- 新增 `knowledge_membership_checkout_locks`，按账号派生确定性文档 ID，并使用
  随机租约 token。租约为 90 秒，commit、bind 和 release 都校验 token；过期
  租约可接管，旧 token 不能覆盖新持有者。
- 历史待确认订单必须先调用微信官方查单：状态 2/3/4 才履约，状态 0/6 才允许
  结束后新建，只有状态 1 可对同一订单重新签名；退款失败、未知状态、金额、账号、
  商品或环境不一致均失败关闭。
- 微信单次外呼最长 5 秒，完整建单外呼预算 22 秒，低于 30 秒云函数超时。
- 发货回调只在验签、字段绑定、官方查单和权益事务全部成功后返回加密成功应答。
  权益事务失败返回 retry；重复回调幂等成功且不重复延长会员。
- 客户端按订单保存 `cashierCompleted`，只在真实、无数字错误码的 iOS 收银台失败
  场景展示 Apple 提示；服务端失败和付款后确认失败使用各自固定文案，原始技术
  文本不暴露给用户。

## 生产恢复与发布

- 先创建并回读 checkout 锁集合，设置 `ADMINONLY`；再应用订单
  `owner_status_created_at` 索引，最后部署 `membershipBilling`。当前生产控制面
  为 26 个合同集合、44 个合同索引、26 份数据库规则，四函数 manifest 0 漂移。
- 最终 `membershipBilling` 已部署并处于 Active/Available；15 分钟对账触发器
  启用。线上计划冒烟为可售、30 天、590 分当前价/商品原价，1090 分仅为界面
  比较价。
- 最新一轮生产定时对账已使用带 `pay_sig` 的手工发货兜底完成，3/3 历史已付款
  订单的本地发货状态均为 `delivered`；没有再次扣款，也没有人工改订单或会员。
- 完整 `npm.cmd run verify` 通过；Node 测试 663/663，项目检查为 32 个 JSON、
  302 个 JavaScript、12 个注册页面，覆盖率为行 80.85%、分支 69.05%、函数
  77.82%，生产依赖审计和 `git diff --check` 均通过。
- 最新开发预览包为 471,387 bytes，包含两步登录、作用域退出、订单阶段恢复、
  双击保护和安全错误文案。开发者工具模拟器不能完成支付，需用真实手机扫描预览码。

## 恢复与资金边界

- 对旧订单只允许微信官方查单推动状态；绝不根据客户端“付款成功”回调、截图、
  数据库残留或人工判断直接授予会员。
- 用户已付款后不要再次购买。应使用同一微信账号打开“我的”，由待确认订单恢复
  和会员刷新展示现有权益。
- 当前实付和会员恢复已经核对；退款、App Store 退款通知以及退款后权益回收仍需
  真实手机资金 canary。支付环境为 `env=0`，会真实扣款。
